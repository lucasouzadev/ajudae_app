## 1. Formulário do Prestador (Mobile) — `provider-validation.tsx`

### O que era
Formulário único de scroll longo com validação básica (boolean `error`), sem máscaras, sem paginação, sem câmera para selfie.

### O que virou
Formulário **paginado em 5 etapas** com:

| Etapa | Conteúdo |
|-------|----------|
| 1 — Dados pessoais | CPF (máscara), data de nascimento (máscara DD/MM/AAAA), telefone (DDD + 9 dígitos) |
| 2 — Tipo de serviço | Cards de seleção (frete / mudança / entrega) + categoria |
| 3 — Veículo | Tipo, modelo, ano, placa (máscara Mercosul/antiga) |
| 4 — Contato | Método (ligação/WhatsApp) + disponibilidade |
| 5 — Documentos | RG, comprovante, CNH, CRLV, selfie — com opção câmera |

**Per-field validation:** cada campo tem `error` (string descritiva), `success` (booleano) e `hint` inline. Exemplos de mensagens:
- `"Placa inválida. Use ABC-1234 (antiga) ou ABC1D23 (Mercosul)."`
- `"CPF inválido. Verifique os dígitos."`
- `"Informe nome e sobrenome (mínimo 2 palavras)."`

**Câmera para selfie:** `DocPickerRow` com prop `isCamera` — abre ActionSheet modal com opções "Câmera" / "Galeria". Usa `ImagePicker.CameraType.front`.

**Animação entre etapas:** `Animated.timing` com `useNativeDriver: false` (width animation).

### Arquivos modificados
- `artifacts/fretex/app/provider-validation.tsx` — reescrito (~580 linhas)
- `artifacts/fretex/app/onboarding.tsx` — Input com `error?: string`, `success?: boolean`, `hint?: string`; câmera para foto de perfil; mensagens de erro descritivas

### Controle de acesso
- Login via Supabase Auth (email + senha)
- A cada restore de sessão, `verifyAndSetSession()` consulta `profiles.role` no banco
- Se `role !== 'admin'` → `signOut()` automático (protege contra TOCTOU)
- Rate limiting in-memory: 5 tentativas / 15 min por e-mail

### Banco — schema do ajudae_banco (rlehpgvvevarpkkamied)
Para habilitar o login admin, executar no SQL Editor do Supabase:
```sql
ALTER TABLE profiles 
  ADD COLUMN IF NOT EXISTS role text NOT NULL DEFAULT 'user' 
  CHECK (role IN ('user', 'admin'));

UPDATE profiles 
  SET role = 'admin' 
  WHERE id = (SELECT id FROM auth.users WHERE email = 'seu-email@exemplo.com');
```

## 3. Segurança Aplicada

### Headers HTTP (`public/_headers` e `vercel.json`)
```
Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; 
  img-src 'self' data: blob: https://*.supabase.co; connect-src 'self' https://*.supabase.co wss://*.supabase.co;
  font-src 'self'; frame-src 'none'; frame-ancestors 'none'; form-action 'self'; base-uri 'self'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Referrer-Policy: strict-origin-when-cross-origin
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

### Signed URLs para documentos
`security.ts` expõe `getSignedUrl(bucket, path)` e `getSignedUrls(bucket, paths)` com TTL de 300s. O bucket `provider-docs` deve ser configurado como **privado** no Supabase Storage.

### Sanitização de output
`sanitizeText(raw)` remove tags HTML, null bytes e caracteres de controle — aplicada em todo conteúdo vindo do banco antes de entrar no estado React.

### Busca sem ReDoS
`Providers.tsx` usa `String.includes()` em vez de regex para o campo de busca. Input limitado a 200 chars (`maxLength`).

### Incident de segurança resolvido
O arquivo `.claude/settings.local.json` continha um JWT do Supabase e foi commitado acidentalmente. Ações tomadas:
1. Arquivo removido do tracking git (`git rm --cached`)
2. `.claude/settings.local.json` adicionado ao `.gitignore`
3. **Usuário instruído a rotacionar a `anon key` no Supabase ajudae_banco** — obrigatório
