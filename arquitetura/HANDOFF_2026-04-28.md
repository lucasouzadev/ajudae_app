## 1. Dashboard do Prestador — Nova Hierarquia

### O que foi feito
A tela `PrestadorHome` foi completamente reestruturada para refletir a **hierarquia de urgência de informação** que o prestador precisa ver ao abrir o app.

### Nova ordem
```
1. Toggle Online/Offline  ← decisão mais importante do dia
2. Aguardando / Nova Solicitação  ← ação imediata necessária
3. Serviço em Andamento (se houver)  ← ação em progresso
4. HotAreaBanner  ← oportunidade de ganho
5. Stats rápidos (Hoje R$, Avaliação, Serviços)  ← contexto
6. Tips "Como ganhar mais"  ← educação
```

### Mudanças visuais
- **Toggle Online**: fundo verde sólido `c.success` + borda `#15803D` + texto/dot brancos quando ativo. Estado offline mantém `c.card` neutro.
- **Card Aguardando**: borda esquerda colorida `c.primary` de 3px + ampulheta animada (flip 180° a cada 700ms via `Animated.timing` loop) + pulse ring.
- **Card Nova Solicitação**: `LinearGradient` na cor da categoria (mudança=amarelo, frete=azul, entrega=verde) + badge "NOVA SOLICITAÇÃO" + pulse scale animation.
- **Todos os cards**: `shadowColor`, `shadowOpacity: 0.12–0.18`, `elevation: 5–8` para destoar do fundo.
- **Portfólio removido do conteúdo** — movido para o bottom-bar (ver seção 2).

### O que o backend precisa suportar
| Campo | Tipo | Uso |
|---|---|---|
| `user.verified` | `boolean` | Toggle bloqueado quando `false` |
| `activeService.status` | `"requested" \| "accepted" \| "en_route" \| "in_progress"` | Determina qual card exibir |
| `activeService.category` | `"Mudança" \| "Frete" \| "Entrega"` | Cor do gradiente do card |
| `activeService.customerName` | `string` | Nome no card |
| `activeService.estimatedPrice` | `number` | Valor líquido = `estimatedPrice * 0.85` |
| `activeService.scheduled` | `boolean` | Label "Agendado" vs "Imediato" |
| Stats: ganhos do dia | `number` | Card stats — campo sugerido: `earningsToday` |
| Stats: avaliação média | `number` | Card stats — campo sugerido: `ratingAvg` |
| Stats: serviços do dia | `number` | Card stats — campo sugerido: `jobsToday` |

## 2. Portfólio — Editor Completo

### O que foi feito
O portfólio saiu de um link simples `router.push("/portfolio")` para um **Modal pageSheet com editor completo** acessível pelo 4º tab do bottom-bar do prestador.

### Estrutura do PortfolioSheet
```
Tab "Visualização"
  ├── Hero gradient (initials + nome + rating)
  ├── Bio
  ├── Banner de promoção (LinearGradient âmbar, se preenchido)
  ├── Lista de serviços (editados)
  ├── Preview do pin como aparece no mapa
  └── Depoimento em destaque (fixo por ora)

Tab "Editar" (seções colapsáveis)
  ├── Bio / Apresentação (textarea 280 chars)
  ├── Serviços em destaque (add/remove/edit, máx 3)
  ├── Promoção ativa (texto 50 chars + data)
  └── Personalizar Pin
       ├── Color picker (6 presets: #FF5500, #2563EB, #16A34A, #9333EA, #D97706, #0EA5E9)
       ├── Icon picker (5 opções: Casa, Van, Caixa, Rápido, Top)
       ├── Mensagem curta (25 chars)
       └── Preview em tempo real
```

### O que o backend precisa suportar
```typescript
interface ProviderPortfolio {
  bio: string;                     // max 280 chars
  services: Array<{
    title: string;
    price: number;
    desc: string;
  }>;                              // max 3 items
  promoText: string | null;        // max 50 chars
  promoDue: string | null;         // "DD/MM" format
  pinColor: string;                // hex color
  pinIcon: string;                 // ionicons key
  pinMessage: string | null;       // max 25 chars
  featuredReviewId: string | null; // referência à review fixada
}
```

**Tabela sugerida:** `provider_portfolios` com FK para `providers.id`  
**Endpoint sugerido:** `PATCH /providers/:id/portfolio`

## 3. Pin Callout — Dois Estados + Auto-Fechamento

### O que foi feito
O mapa do cliente (`ClienteHome`) agora tem uma lógica de dois toques no pin:

```
Toque 1 → Pin transforma em activeCard overlay no mapa
            (cor do prestador, nome, distância, preço, hint de "toque novamente")

Toque 2 → Fecha activeCard + abre ProviderModal completo

Sheet expandido → activeCard fecha automaticamente
```

### Lógica de auto-fechamento
```typescript
sheetHeightAnim.addListener(({ value }) => {
  if (value > COLLAPSED_H + 20 && pinCardVisible) {
    setActive(null);
    setPinCardVisible(false);
  }
});
```

**Regra de negócio:** quando o usuário puxa o sheet para ver a lista de prestadores (mapa compacto), qualquer pin em foco é fechado automaticamente para evitar sobreposição visual.

### O que o backend precisa suportar
O mapa hoje usa `MOCK_PROVIDERS` com coordenadas fixas `lat/lng`. Para o mapa real:

```typescript
interface ProviderMapPin {
  id: string;
  name: string;
  initials: string;
  color: string;                // cor do pin (customizável via portfólio)
  icon: string;                 // ícone do pin (customizável via portfólio)
  pinMessage: string | null;    // mensagem curta do pin
  category: "Mudança" | "Frete" | "Entrega";
  price: string;               // "R$89" — preço de exibição no pin
  priceFrom: number;           // valor numérico
  lat: number;                 // latitude real (Google Maps / Mapbox)
  lng: number;                 // longitude real
  isOnline: boolean;
  rating: number;
  distance: number;            // km — calculado no backend ou cliente
}
```

**Endpoint sugerido:** `GET /providers/nearby?lat=X&lng=Y&radius=5&category=Todos`  
**Atualização:** WebSocket ou polling a cada 10s para posições em tempo real.

```

```

```
POST /orders                          → criar pedido
GET  /orders/:id                      → estado atual do pedido
PATCH /orders/:id/status              → aceitar, en_route, in_progress
```

```
GET  /providers/:id/portfolio         → portfólio público
GET  /providers/:id/pin               → dados do pin customizado (cor, ícone, mensagem)
```

## 8. Decisões de Design Registradas

| Decisão | Motivo | Alternativa rejeitada |
|---|---|---|
| Portfolio como Modal pageSheet (não rota) | Evita perder estado do dashboard; mais natural como sheet de edição | `router.push("/portfolio")` — perdia contexto |
| Pin auto-fecha com sheet expandido | Evita sobreposição visual entre pin card e lista de prestadores | Pin ficar visível com sheet expandido — visualmente poluído |
| Toggle online com fundo verde sólido | Alta diferenciação visual — o prestador precisa saber instantaneamente seu estado | Apenas borda colorida — não era suficientemente óbvio |
| Mapa fullscreen com safe-area preta | Mapa SVG não tem controle de z-index para evitar status bar — espaço preto é mais limpo | `paddingTop` no mapa — distorcia proporções do SVG |
| `#EDEAE3` no marketplace | Fundo muito claro diluía os cards brancos — tom bege levemente mais escuro cria contraste natural | Fundo `c.background` original — misturava-se com os cards |
