## 1. Bug Fixes

### 1.1 `crypto.subtle.digest` — crash no ServiceContext

**Problema:** `crypto.subtle.digest` (Web Crypto API) não existe em React Native → `ReferenceError: Property 'crypto' doesn't exist` na geração do commitment hash.

**Solução:** Implementação pura em JS de dois passes:
```typescript
// contexts/ServiceContext.tsx
function djb2Hash(str: string): string {
  let h = 5381;
  for (let i = 0; i < str.length; i++) {
    h = ((h << 5) + h) ^ str.charCodeAt(i);
    h = h >>> 0;
  }
  let h2 = 0x811c9dc5; // segundo passe FNV-like
  for (let i = str.length - 1; i >= 0; i--) {
    h2 = ((h2 ^ str.charCodeAt(i)) * 0x01000193) >>> 0;
  }
  return (h >>> 0).toString(16).padStart(8, "0") + (h2 >>> 0).toString(16).padStart(8, "0");
}
```

Produz 16 hex chars (64-bit). Funciona offline, sem dependências. **Migrar para HMAC-SHA256 via `expo-crypto` antes de produção.**

```typescript
const handleLocate = async () => {
  setLocating(true);
  Animated.loop(Animated.timing(locateSpin, { toValue: 1, duration: 600, useNativeDriver: true })).start();
  try { await mapRef.current?.recenter(); } catch {}
  locateSpin.stopAnimation(); locateSpin.setValue(0);
  setLocating(false);
};
```

## 2. Sistema de Push Notifications

### 2.1 Arquitetura

```
NotificationContext
  ├── setNotificationHandler (foreground: showAlert + playSound + setBadge)
  ├── CATALOG: 22 event templates → { title, body, data.screen }
  ├── fire(event, vars): scheduleNotificationAsync(trigger: null) — dispara imediatamente
  └── NotificationProvider
        ├── usa usePermissions().notifications.granted (delegado)
        ├── obtém push token via getExpoPushTokenAsync()
        └── Watcher reativo:
              refs: prevStatus, prevStartAttempts, prevEndAttempts, isInitialLoad
              deps: [active?.status, active?.startPinAttempts, active?.conclusionAttempts]
```

### 2.2 Regras do watcher

| Condição | Ação |
|---|---|
| `active === null` | Reset refs; `isInitialLoad = true` |
| Primeira render com `active` (hydration) | Snapshot refs; não dispara notificação |
| `status` mudou E não é PIN dispute | Dispara notificação de status (role-specific) |
| `startPinAttempts` aumentou E status `disputed` | Dispara `pin_start_disputed` (não `service_disputed` duplicado) |
| `startPinAttempts` aumentou E status ≠ `disputed` | Dispara `pin_start_wrong` com `{ left: 5 - attempts }` |
| `conclusionAttempts` aumentou | Mesma lógica com `pin_end_*` |

### 2.3 Canais Android

| Canal | Importância | Uso |
|---|---|---|
| `ajudae-default` | MAX | Auth, mensagens, pagamentos |
| `ajudae-service` | HIGH | Mudanças de status do serviço |
| `ajudae-jobs` | MAX | Novo pedido para prestador |

### 2.4 Navegação por tap

```typescript
// app/_layout.tsx — dentro de AuthGate
useEffect(() => {
  const sub = Notifications.addNotificationResponseReceivedListener((response) => {
    const screen = response.notification.request.content.data?.screen;
    if (screen && isAuthenticated) router.push(`/${screen}` as never);
  });
  return () => sub.remove();
}, [isAuthenticated]);
```

### 2.5 O que o backend precisa suportar

Para **push notifications em background** (quando app está fechado):
- Armazenar push token em `profiles.push_token`
- Endpoint: `POST /notifications/send` → body: `{ userId, event, vars }`
- O `pushToken` já é capturado e exposto via `useNotification().pushToken`

Para **notificações de novos pedidos** ao prestador em background:
- Webhook no backend ao criar pedido → enviar push para todos prestadores online na área

## 3. Sistema de Permissões LGPD-Compliant

### 3.1 Campos de banco utilizados

Todos em `public.profiles` (já existiam):

| Campo | Tipo | Descrição |
|---|---|---|
| `lgpd_accepted` | `boolean` | Consentimento LGPD — fonte de verdade no DB |
| `geolocation_requested` | `boolean` | `true` quando OS permission granted |
| `camera_requested` | `boolean` | `true` quando camera OU mediaLibrary granted |
| `notifications_requested` | `boolean` | `true` quando notification permission granted |
| `last_consent_update` | `timestamp` | Atualizado em toda mudança de consentimento |

### 3.2 PermissionsContext — comportamento

```typescript
// Leitura no boot (e a cada retorno ao foreground via AppState):
const [locResult, camResult, libResult, notifResult] = await Promise.all([
  Location.getForegroundPermissionsAsync(),
  ImagePicker.getCameraPermissionsAsync(),
  ImagePicker.getMediaLibraryPermissionsAsync(),
  Notifications.getPermissionsAsync(),
]);

// OsPermission: { granted: boolean, canAsk: boolean }
// canAsk = false quando permanentemente negado → deve abrir OS Settings
```

**Sync automático para Supabase** quando qualquer permissão muda (via `useEffect` nos deps):
```typescript
supabase.from("profiles").update({
  geolocation_requested: location.granted,
  camera_requested: camera.granted || mediaLibrary.granted,
  notifications_requested: notifications.granted,
  lgpd_accepted: lgpdAccepted,
  last_consent_update: new Date().toISOString(),
}).eq("id", user.id);
```

**LGPD**: AsyncStorage como cache offline (`@ajudae_lgpd_accepted = "1"`) + DB como fonte de verdade quando autenticado.

### 3.3 PermissionGate — fluxo

```
isAuthenticated && ready
  └─ !lgpdAccepted → Tela LGPD (Modal, animationType: "slide", não dispensável)
       └─ aceitar → acceptLGPD() → AsyncStorage + Supabase
           └─ !location.granted && location.canAsk → Tela Localização
               └─ permitir → requestLocation()
               └─ pular → próximo
           └─ !notifications.granted && notifications.canAsk → Tela Notificações
               └─ permitir → requestNotifications()
               └─ pular → AsyncStorage.setItem(ONBOARDING_KEY, "1")
               └─ step = "done" → null (gate desaparece)
```

Flag `@ajudae_perm_onboarding_shown = "1"` evita re-exibir as telas de permissão em sessões futuras.

### 3.4 ProfileOverlay — Configurações

Para cada permissão OS:
```
granted = true  → toggle verde + sub "Ativa" / "Ativo"
canAsk = true   → toggle cinza + sub "Toque para ativar" → onPress: requestXxx()
canAsk = false  → ícone open-outline laranja + sub "Abrir Configurações" → Linking.openSettings()
```

### 3.5 Conformidade LGPD (Lei 13.709/2018)

| Requisito | Implementado |
|---|---|
| Identificar o controlador | ✅ Nome "Ajudaê" na tela de LGPD |
| Especificar finalidade de cada categoria de dado | ✅ 4 categorias explicadas (localização, câmera, notificações, identidade) |
| Links para Política de Privacidade e Termos | ✅ `Linking.openURL("https://ajudae.com.br/privacidade")` |
| Consentimento ativo (não pré-marcado) | ✅ Usuário deve tocar "Aceitar e continuar" |
| Registro de consentimento | ✅ `lgpd_accepted + last_consent_update` em Supabase |
| Direito de exclusão | ✅ Menção ao menu "Excluir conta" na tela de LGPD |

**Pendente para produção:**
- Implementar `DELETE /users/me` (backend) para exclusão real
- Política de Privacidade e Termos de Uso em URLs reais
- Adicionar passo de câmera no `PermissionGate` para prestadores (camera é pedida só quando necessário agora)
